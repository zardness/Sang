# 레아 결과 보고: 시장노트

## 무엇을 분석했나
레퍼런스 이미지 6장을 화면 단위로 판독했습니다: 레이아웃 그리드, 컴포넌트, 상태(접힌 메뉴, 열린 AI 패널, 툴팁, 선택된 탭·기간), 문구, 숫자. 이미지 픽셀을 샘플링해 색을 뽑았습니다(`analysis/design-tokens.json`).

화면 속 숫자끼리의 관계도 맞춰 봤습니다. 이 과정에서 서버 로직 몇 가지를 거꾸로 알아냈습니다.
- 보고서 항목 점수 18+17+16+11+20 = 82점이므로 총점은 단순 합이고, 각 항목은 20점 만점입니다.
- "0.07%와 0.25% 차이, 1,000만원 10년 ≈ 33만원"은 연 6.5% 수익을 가정해야 나오는 값입니다.
- 코스피 +1.16%, 코스닥 +0.54% 인 날의 헤드라인이 "대형주가 시장을 끌어올렸어요"입니다.

## 추정 기술 스택 (원본)
SPA(React 계열) + 차트 라이브러리 또는 SVG, Pretendard 글꼴, RAG(유사도 0~1 점수를 그대로 보여 줌), 시계열 예측 모델(LSTM 표기). 백엔드는 화면만으로는 알 수 없습니다.

## 재구현
React 18 + Vite + TypeScript / Hono + Node 내장 SQLite. 외부 서비스 없이 로컬에서만 동작합니다.

## 추론한 서버 로직: 11건
확신도 높음 2 · 중간 7 · 낮음 2. 확신도가 낮은 항목은 다음 두 가지입니다.
- INF-010: AI 패널을 열면 메뉴를 접는다
- INF-011: 브리핑 4건의 구성

전체 목록은 [INFERENCE.md](INFERENCE.md)에 있습니다. 원본의 'LSTM 예측'은 설명 가능한 통계 모델로 바꿨고, 화면에도 "통계 모델"이라고 표시합니다.

## 원본보다 나아진 점
1. 화면마다 정적이던 숫자가 실제 데이터와 API로 동작합니다. 업로드, 채점, 다시 평가, 질문, 진행률, 관심 종목이 모두 저장됩니다.
2. 고정 문장이던 총보수 설명을 계산기로 바꿨습니다.
3. 보고서 평가 기준과 항목별 신호를 공개하고, 제안을 눌러 바로 적용할 수 있습니다.
4. 통합 검색, 알림 드롭다운, 키보드 조작, 모바일(390px) 대응을 넣었습니다.
5. 메뉴만 있던 투자 전략(적립식 시뮬레이터)과 설정 화면을 새로 만들었습니다.

## 검증
- 단위·API 테스트 17개 통과 (`npm test`): 화면 값 재현, 예측 밴드 성질, 채점 규칙, RAG 근거 선택, API 오류 처리
- E2E 시나리오 8개 통과 (`npm run test:e2e`): 랜딩 검색 → ETF, 대시보드 전환·툴팁, ETF 탭·관심 종목·리포트 생성, 학습 용어·완료, 보고서 업로드·제안 적용·점수 상승, AI 질문, 모바일 가로 넘침 없음, 런타임 오류 0
- 원본 대비 스크린샷 비교 (`analysis/rebuild/compare-*.png`):

| 화면 | 픽셀 차이 | 블록(레이아웃) 차이 |
| --- | --- | --- |
| 랜딩 | 6.5% | 5.3% |
| 대시보드 | 4.6% | 6.3% |
| ETF 상세 | 5.7% | 7.4% |
| 학습 | 6.3% | 7.6% |
| 보고서 평가 | 5.5% | 6.3% |
| AI 질문 | 4.0% | 4.0% |

차이는 대부분 가상 시세로 그린 차트의 모양, 추가한 요소(관심 종목 별, 추론 태그, 계산기 입력칸), 답변 문장의 차이입니다.

## 하지 않은 것과 이유
- 실제 로그인·결제는 만들지 않았습니다. 원본처럼 보이는 인증 화면은 피하고, 데모 계정 버튼만 둡니다.
- 원본 서비스에 접속해 수집하지 않았습니다. 입력이 이미지뿐이었기 때문입니다.
- PDF/Word 본문 추출은 지원하지 않습니다. 의존성을 늘리지 않으려고 .txt/.md 와 붙여 넣기만 받습니다.
- RAG 유사도 값의 크기가 원본(0.77~0.91)보다 작습니다(0.2~0.4). 임베딩 대신 TF-IDF를 쓰기 때문이며, 순서를 정하는 데는 문제가 없습니다.
