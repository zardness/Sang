LangChain · Chroma · Pinecone RAG 핵심요약
(첨부 ch09_06~09 노트북 4개 기준 / API 호출·문서 업로드는 실행하지 않음)

1장 전체 구성
    -ch09_06: OpenAI 임베딩 + 로컬 Chroma + ChatOpenAI로 RAG 구현
    -ch09_07: Upstage 임베딩 + 로컬 Chroma + ChatUpstage로 RAG 구현
    -ch09_08: Upstage 임베딩 + Pinecone 검색 예제. 모델 import 등에 수정 필요
    -ch09_09: OpenAI 임베딩 + Pinecone 업로드·검색 + ChatOpenAI 답변 생성
    -공통 흐름: DOCX 읽기 → 청크 분할 → 임베딩 → 벡터 DB 저장 → 관련 문서 검색 → 답변 생성
    -이전 인메모리 예제에서 로컬 파일 저장과 클라우드 저장으로 확장한 내용

2장 문서 읽기와 청크 분할
    -Docx2txtLoader(): 소득세법 DOCX 문서를 읽는 로더
    -loader.load(): 문서 불러오기 / load_and_split(): 읽은 문서를 지정한 방식으로 분할
    -Document.page_content에는 텍스트, metadata에는 출처 등의 부가정보가 들어감
    -TokenTextSplitter(chunk_size=1500, chunk_overlap=200): 토큰 기준으로 분할
    -RecursiveCharacterTextSplitter(chunk_size=1500, chunk_overlap=200): 기본 설정에서 문자 수 기준으로 분할
    -재귀 문자 분할은 문단·줄바꿈·공백 등의 경계를 순차적으로 고려
    -chunk_overlap은 앞뒤 청크가 일부 문맥을 공유하도록 하는 설정
    -토큰 1500개와 문자 1500개는 서로 다른 분량
    -len(document.page_content)는 글자 수이며 토큰 수를 뜻하지 않음
    -06·07을 위에서부터 실행하면 documents가 문자 기반 분할 결과로 다시 저장됨

3장 임베딩 모델
    -임베딩은 문서를 검색 가능한 숫자 벡터로 변환하는 작업
    -OpenAIEmbeddings(model='text-embedding-3-large'): OpenAI 임베딩 예제
    -UpstageEmbeddings(model='solar-embedding-1-large-passage'): Upstage 임베딩 예제
    -embed_query(문자열): 질문 등 하나의 문자열을 벡터로 변환
    -embed_documents(문자열 목록): 여러 문서를 벡터로 변환
    -len(embedding.embed_query('샘플'))로 실제 출력 차원을 확인하는 코드 포함
    -문서 저장과 질문 검색에는 호환되는 동일 임베딩 체계를 사용해야 함
    -차원이 같더라도 서로 다른 모델의 벡터를 섞으면 의미 있는 비교가 되지 않을 수 있음
    -답변 생성 LLM과 검색용 임베딩 모델은 역할이 다르며 별도로 설정

4장 Chroma 로컬 저장과 재사용
    -Chroma는 이 예제에서 collection 단위로 벡터와 문서를 관리
    -Chroma.from_documents(documents=..., embedding=...): 문서를 임베딩해 저장하는 흐름
    -persist_directory는 로컬 저장 폴더, collection_name은 컬렉션 이름
    -06의 폴더는 ./chroma, 07의 폴더는 ./chroma_upstage
    -컬렉션 이름은 두 예제 모두 tax-collection
    -기존 저장소 연결: Chroma(embedding_function=..., persist_directory=..., collection_name=...)
    -연결할 때는 저장 당시의 폴더·컬렉션·임베딩 설정을 맞춤
    -get(include=['embeddings','documents','metadatas'])로 저장 내용 확인
    -06·07에서는 최초 저장 코드가 주석 처리되어 있으므로 기존 데이터가 있어야 검색 가능
    -저장소에 연결하는 것만으로 현재 documents가 자동 등록되는 것은 아님

5장 유사도 검색과 Retriever
    -database.similarity_search(query=질문, k=2): 관련 문서 최대 2개 검색
    -검색 결과는 Document 목록이며 page_content를 꺼내 답변 문맥으로 사용
    -'\n--\n'.join(...)으로 검색 문서를 구분해 하나의 문자열로 연결
    -as_retriever(): 벡터 저장소를 LangChain 검색 단계로 사용할 수 있게 변환
    -search_type='similarity': 유사도 기반 검색
    -search_kwargs={'k':3}: 검색 결과 수 설정
    -주석 예제의 mmr는 관련성과 결과 다양성을 함께 고려하는 검색 방식
    -fetch_k는 MMR 후보 수, lambda_mult는 관련성과 다양성의 균형 설정
    -similarity_score_threshold는 점수 기준을 넘는 결과를 찾는 방식
    -검색 문서 수가 많다고 항상 답변 품질이 좋아지는 것은 아니므로 관련성 확인 필요

6장 프롬프트와 RAG 체인
    -검색 문맥(context)과 사용자 질문(question 또는 query)을 함께 LLM에 전달
    -ChatPromptTemplate으로 역할·문맥·질문을 포함한 입력 틀 생성
    -예제 지시: 문맥을 참고하고, 모르면 모른다고 답하며, 최대 3문장으로 작성
    -ChatOpenAI 또는 ChatUpstage의 invoke()로 답변 생성
    -StrOutputParser(): AIMessage를 답변 문자열로 변환
    -기본 체인: promptTemplate | llm | outputParser
    -자동 검색 체인의 구성:
        {'context': retriever | format_documents,
         'query': RunnablePassthrough()}
        | prompt | llm | StrOutputParser()
    -RunnablePassthrough()는 입력 질문을 그대로 query에 전달
    -같은 질문이 검색 단계에도 전달되고 검색 결과는 context에 들어감
    -rag_chain.invoke(질문)으로 검색부터 답변까지 연결 실행
    -RAG는 관련 문서를 참고하게 하는 방식이며 모델 자체를 재학습하는 작업은 아님

7장 Pinecone 클라우드 저장과 검색
    -이 예제의 Chroma는 로컬 폴더, Pinecone은 클라우드 index에 저장
    -PINECONE_API_KEY를 .env에 등록하고 load_dotenv()로 로드
    -Pinecone()은 서비스 클라이언트, PineconeVectorStore는 LangChain 연동 객체
    -PineconeVectorStore.from_documents(): 문서 임베딩과 지정 인덱스에 업로드
    -PineconeVectorStore(embedding=..., index_name=...): 기존 인덱스 연결
    -09에서는 index_name='tax-index-openai'로 업로드
    -인덱스 생성 코드는 첨부에 없으므로 인덱스와 차원 설정이 사전에 준비되어 있어야 함
    -검색은 similarity_search(query, k=3)로 수행
    -찾은 문서들을 연결하고 ChatOpenAI(model='gpt-4.1-nano')에 질문과 함께 전달
    -문서를 매번 다시 업로드하기보다 최초 등록과 이후 검색 실행을 구분

8장 임베딩 차원과 모델 일치
    -임베딩 벡터의 길이와 Pinecone 인덱스의 dimension은 일치해야 함
    -예: 벡터가 3072차원인데 인덱스가 2048차원이면 저장할 수 없음
    -현재 임베딩 출력 길이를 확인하고 그 설정에 맞는 인덱스를 선택·준비
    -모델이나 출력 차원을 바꿀 때는 기존 문서 벡터와 질문 벡터의 호환성도 확인
    -벡터 일부를 임의로 잘라 길이만 맞추는 방식은 피하고 임베딩 설정을 일관되게 사용
    -09에서는 UpstageEmbeddings를 만든 뒤 같은 embedding 변수에 OpenAIEmbeddings를 다시 대입
    -따라서 순서대로 실행하면 09의 실제 업로드에는 OpenAI 임베딩이 사용됨
    -08은 embedding과 embeding이 다른 변수이므로 OpenAI 객체를 만들어도 실제 DB 연결은 Upstage embedding을 사용

9장 주요 오타와 실행 주의사항

    -원본 DOCX·기존 Chroma 폴더·Pinecone 인덱스는 첨부되지 않아 실제 검색·답변 결과는 검증하지 않음
    -이 자료는 소득세법을 예제 문서로 사용하는 코드 요약이며 세액 계산 결과를 검증한 자료는 아님
