HTML 폼 · 유효성 검사 · 정규표현식 · 레이아웃 요점 정리
대상: 첨부 HTML 10개. 06번과 6번의 블록·인라인 예제는 내용이 같다.
※ 소스 내용 기준 요약이며, 서버 전송이나 회원가입 기능을 실행한 결과는 아니다.

1장 form 태그 기본 (1_form태그기본)
    -form: 사용자 입력값을 모아 서버에 전송하는 영역.
    -action: 전송할 주소. 예제처럼 빈 값이면 현재 문서 주소로 제출한다.
    -method: 전송 방식. 생략하면 GET이 기본이다.
    -GET: 입력값을 URL의 쿼리 문자열로 전달한다.
    -POST: 입력값을 요청 본문으로 전달한다. POST 자체가 암호화는 아니다.
    -input type="text": 일반 문자열 입력.
    -input type="password": 입력 문자를 가려 표시한다.
    -name: 전송할 데이터의 이름. 예제에서는 uid, upw를 사용한다.
    -input type="submit": 폼 제출 버튼. value는 버튼에 표시할 문구다.
    -width: 280px; margin: 10px auto; → 표 너비 280px, 위·아래 여백 10px,
      좌·우 자동 여백으로 표를 가로 가운데 배치한다.
    -소스 수정점: 비밀번호 input 앞에 <td>가 빠져 있다.
      colspan="=2"는 colspan="2"로 수정하고 </form>을 추가한다.
    -주석의 methode는 method의 오타다.
    -로그인 비밀번호를 GET으로 보내면 URL에 포함된다. 실제 로그인은 HTTPS와
      POST를 사용하고, 서버에서 인증을 처리해야 한다.

2장 다양한 입력 양식 (2_입력양식들)
    -hidden: 화면에 보이지 않는 값을 전송한다. 비밀값을 보호하는 기능은 아니다.
    -button: 일반 버튼. 예제의 '중복확인' 버튼에는 처리 코드가 없다.
    -tel: 전화번호 입력용. 이 타입만으로 전화번호 형식을 검사하지는 않는다.
    -number: 숫자 입력. 예제는 min="0", max="60", value="0"으로 경력을 설정한다.
    -email: 이메일 형식 입력 및 기본 형식 검사.
    -file: 파일 선택. date: 날짜 선택.
    -radio: 같은 name을 가진 항목 중 하나를 선택한다. 예제는 성별 선택이다.
    -checkbox: 여러 항목 선택 가능. 예제는 한국어·영어·중국어 선택이다.
    -checked: 처음부터 선택된 상태.
    -select / option: 선택 목록과 각 항목.
    -option에 value가 있으면 그 값, 없으면 항목 텍스트가 전송값이 된다.
    -multiple: 여러 항목 선택 허용. select의 size="3"은 표시할 행 수다.
    -textarea: 여러 줄 입력. cols와 rows로 표시 크기를 지정한다.
    -reset: 입력을 초기 상태로 되돌린다. 항상 모든 값을 비우는 것은 아니다.
    -input의 size: 화면상 입력칸 너비 기준이며 입력 글자 수 제한은 아니다.
    -autocomplete="off": 자동 완성 사용을 끄도록 요청한다.
    -range 예제는 주석 처리되어 실행되지 않는다. color와 url은 설명만 있다.
    -파일 내용을 업로드하려면 form에 method="post"와
      enctype="multipart/form-data"를 지정하고 서버 처리 기능을 구현해야 한다.

3장 JavaScript로 게시판 입력 검사 (3_개시판)
    -제목, 작성자, 본문, 첨부파일 입력칸으로 게시판 작성 화면을 구성한다.
    -onsubmit="return chk()": 제출 시 chk()의 반환값으로 제출 여부를 결정한다.
    -trim(): 문자열 양끝 공백을 제거한다.
    -!문자열: 빈 문자열인지 검사하는 용도로 사용한다.
    -length: 문자열 길이. 작성자 이름을 공백 제거 후 2글자 이상인지 검사한다.
    -alert(): 안내창 표시. focus(): 잘못 입력한 칸으로 입력 초점 이동.
    -return false: 폼 제출을 막는다.
    -현재 코드는 마지막에도 return false이므로 정상 입력해도 제출되지 않는다.
      검사를 통과했을 때 제출하려면 마지막 반환값을 true로 바꾼다.
    -폼은 document.forms['frm'], 입력칸은 form.elements['title']처럼
      명시적으로 찾으면 전역 이름이나 폼의 기본 속성과 충돌하는 문제를 줄인다.
    -border-collapse: collapse; → 표 셀의 경계선을 합쳐 표시한다.
    -td, th { padding: 5px 10px; } → 셀 안쪽 위·아래 5px, 좌·우 10px 여백.
    -span의 빨간색과 굵은 글씨로 필수 입력 표시(*)를 강조한다.

4장 HTML 속성으로 입력 검사 (3_개시판2)
    -required: 값을 반드시 입력하도록 한다.
    -minlength="2": 입력 문자열의 최소 길이를 2로 지정한다.
    -예제는 작성자 입력칸에 두 속성을 적용하여 브라우저 기본 검사를 사용한다.
    -required와 minlength는 trim()처럼 공백을 제거하지 않으므로,
      공백만 입력한 이름을 별도로 검사할 필요가 있다.
    -이 파일에는 제목 입력 행이 없고, 표 안에 불필요한 문자 'ㅍ'이 들어 있다.
    -클라이언트 검사는 입력 안내용이며, 실제 저장 전에는 서버에서도 검증한다.

5장 비밀번호 확인 검사 (4_pw유효성검사)
    -의도한 순서: 아이디 4글자 이상 → 비밀번호 4자리 이상 → 확인값 일치 검사.
    -불일치하면 두 비밀번호 칸을 비우고 첫 비밀번호 칸에 초점을 돌리는 구조다.
    -placeholder: 입력 전 도움말. 실제 입력값이나 필수 입력 조건이 아니다.
    -label의 for와 input의 id를 맞추면 레이블이 해당 입력칸과 연결된다.
    -현재 소스는 문법 오류가 있어 그대로는 검사가 정상 실행되지 않는다.
    -수정할 핵심:
      ① if / else if 블록과 함수의 중괄호 위치를 맞춘다.
      ② alert 문자열에 빠진 닫는 따옴표를 추가한다.
      ③ return false()는 return false;로 고친다.
      ④ 함수 이름 infoChk와 onsubmit의 chk를 infoChk로 통일한다.
      ⑤ 확인칸의 name="pwchk", id="pwChk" 및 코드의 참조 이름을 통일한다.
      ⑥ 모든 조건을 통과하면 return true;로 제출을 허용한다.
    -4자리 조건은 이 예제의 연습 기준이며, 실제 서비스의 비밀번호 정책과는 별개다.

6장 정규표현식과 pattern (5_정규표현식)
    -정규표현식: 문자열이 정해진 형식에 맞는지 검사하는 규칙.
    -\d: 숫자. \D: 숫자가 아닌 문자.
    -\w: 기본적으로 영문자·숫자·밑줄(_). 소스 설명에는 밑줄이 빠져 있다.
    -\W: \w에 해당하지 않는 문자.
    -\s: 공백·탭·줄바꿈 등 공백 문자. \.: 실제 마침표 문자.
    -.: 기본적으로 줄바꿈 문자를 제외한 임의의 문자.
    -{n}: 정확히 n회. {n,}: n회 이상. {2,4}: 2~4회 반복.
    -?: 0회 또는 1회. +: 1회 이상. *: 0회 이상.
    -[...]: 문자 집합. (...): 그룹. |: 또는. ^ / $: 시작 / 끝 위치.
    -input의 pattern은 입력값 전체가 패턴에 맞는지 검사한다.
    -연락처 패턴: \d{2,3}-?\d{3,4}-?\d{4}
      → 숫자 2~3개 + 선택적 하이픈 + 숫자 3~4개 + 선택적 하이픈 + 숫자 4개.
    -하이픈 두 곳을 각각 선택 사항으로 두어 일부 위치에만 하이픈이 있어도 통과한다.
    -연락처에는 required가 있어 빈 값은 허용하지 않는다.
    -이메일 패턴: \w[a-z0-9_\.]{3,}@\w+(\.\w+){1,2}
      → @ 앞 최소 4글자, @ 뒤에는 점으로 구분된 부분을 1~2개 허용하는 예제다.
    -이 이메일 패턴은 모든 유효한 이메일 주소를 포괄하지 않는 연습용 규칙이다.
    -이메일에는 required가 없어 빈 값은 허용된다.
    -fieldset / legend: 관련 입력칸을 묶고 그룹 제목을 표시한다.
    -autofocus: 초기 초점 지정. title: 입력 형식 안내 문구.
    -주석의 생년월일·주민번호 패턴은 형태 검사 예시이며 실제 날짜의 존재나
      번호의 유효성을 모두 검증하지 않는다. 일부 주석 패턴에는 월 00 허용 등 오류가 있다.

7장 블록과 인라인 (06번·6번 공통)
    -두 파일의 내용은 동일하다.
    -p, div, ul 등은 기본적으로 블록 배치되어 새 줄에서 시작한다.
    -li는 기본 display가 list-item이며, 예제에서는 각 항목이 세로로 배치된다.
    -span은 대표적인 인라인 요소로, 텍스트 흐름 안에서 나란히 배치된다.
    -div: 특별한 의미 없이 큰 영역을 묶는다. span: 글이나 작은 부분을 묶는다.
    -p, li, div에는 빨간 테두리, ul에는 파란 테두리를 적용해 영역을 확인한다.
    -CSS display 설정에 따라 기본 배치 방식은 바뀔 수 있다.

8장 div로 공간 나누기 (7_공간분할태그)
    -div의 id를 header, nav, content, footer로 지정하여 영역을 나눈다.
    -header 영역: 회사 이름이나 로고. nav 영역: 메뉴.
    -content 영역: 제목과 본문. footer 영역: 주소·연락처·저작권 안내.
    -#footer p: id가 footer인 요소 내부의 모든 p 요소를 선택한다.
    -margin: 0; color: gray; font-size: 10pt;
      → 하단 문단의 바깥 여백 제거, 회색 글자, 10포인트 크기 적용.
    -이 예제는 영역을 위에서 아래로 배치하며 별도 다단 배치 코드는 없다.

9장 시맨틱 태그로 공간 나누기 (8_공간분할태그)
    -시맨틱 태그: 영역의 의미와 역할이 드러나는 태그.
    -header: 도입부. nav: 주요 탐색 영역. section: 주제별 구역. footer: 하단 정보.
    -div와 id로 표현했던 영역을 의미 있는 태그로 바꾸어 문서 구조를 명확히 한다.
    -footer p: footer 태그 내부의 p를 선택한다. #footer p와 선택 대상이 다르다.
    -화면의 상세한 위치와 디자인은 별도의 CSS로 조절한다.
    -소스의 <section/>은 닫는 태그가 아니다. </section>으로 수정해야 한다.

핵심 정리
    -form = 입력값 제출 / name = 전송 항목 이름 / id = 요소 식별 및 label 연결.
    -required·minlength·pattern = 브라우저 입력 검사.
    -onsubmit + 반환값 = JavaScript로 제출 허용 또는 차단.
    -div·span = 일반 영역 묶기 / 시맨틱 태그 = 영역의 역할 표현.
    -이 자료는 화면과 검사 예제이며 실제 로그인·게시글 저장 서버는 포함하지 않는다.
